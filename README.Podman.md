### Building and running

Containers run with [Podman](https://podman.io); Docker isn't used. On macOS, start Podman's
VM once with `podman machine init && podman machine start`. `podman compose` also needs
`podman-compose` (`brew install podman-compose`).

```bash
make run headless   # podman compose up --build -d, wait for Grafana, open it
make logs           # podman compose logs -f server: the simulation's console
make stop           # podman compose down: the simulation saves its Hall of Fame first
make clean-data     # podman compose down --volumes: also deletes the metrics and Grafana data
```

`make run headless` refuses to start while another simulation is running, locally or in a
container. It always rebuilds the image, so after a code change, `make stop` then
`make run headless` runs the new code. `make run watch` opens a read-only UI next to it that
reloads whenever the container saves new best brains.

`compose.yaml` runs three services:
- `server`: `game_headless.py` in a Python 3.12 image, with raw metrics on
  http://localhost:8000;
- `prometheus`: scrapes the simulation every 5 s (http://localhost:9090) and keeps its data
  in the `prometheus-data` volume;
- `grafana`: http://localhost:3000, with no login and the evolution dashboard as the home
  page. It keeps its database in the `grafana-data` volume.

The volumes survive `make stop`; `make clean-data` deletes both, to start Prometheus and
Grafana from scratch. The brains in `saved_brains/` are not touched.

The image installs `requirements-headless.txt` (the dependencies from `pyproject.toml`
without pygame), so keep the two in step.

The monitoring config lives in `monitoring/`: the Prometheus scrape job, and Grafana's
provisioned data source and dashboard. The dashboard itself is `grafana_dashboard.json`,
generated by `monitoring/dashboard.py`.

### Saved brains

`saved_brains/` is mounted into the container, so the simulation starts from your
`best_brain_*.json` and overwrites them with new Hall of Fame brains as it runs (at most once
per `AUTOSAVE_INTERVAL` ticks, and on stop). Like a local run, it saves a brain that beats the
*faded* score of the previous one, so a file's score can go down. Each start snapshots the
previous pair into `saved_brains/history/`. Don't run `game.py` on the same folder at the
same time: both write the best brain files.

### Deploying to the cloud

Build the image, e.g.: `podman build -t evolution .`.
If your cloud uses a different CPU architecture than your development machine (e.g. you
are on Apple Silicon and your cloud provider is amd64), build for that platform:
`podman build --platform=linux/amd64 -t evolution .`.

Then push it to your registry, e.g. `podman push evolution myregistry.com/evolution`.

The image contains the best brains as they were at build time, so it can start without the
mount. Mount a persistent volume at `/app/saved_brains`, writable by uid 10001, to keep what
it learns across restarts. Prometheus and Grafana are not part of the image.
